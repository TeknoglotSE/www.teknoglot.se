{{- /* Tag cloud. Hexo's helper (node_modules/hexo/dist/plugins/helper/tagcloud.js) does NOT scale linearly with a tag's post count. It sorts the DISTINCT counts, then places each tag by the RANK of its count among them: sizes = distinct counts, ascending ratio = sizes.indexOf(tag.length) / (sizes.length - 1) size = min_font + (max_font - min_font) * ratio style = font-size: parseFloat(size.toFixed(2))px With distinct counts {1,2,3,4,7,8,9,13,28} that yields 10, 11.25, 12.5, 13.75, 15, 16.25, 17.5, 18.75, 20 px. A linear-in-count reading of the formula would give, say, 10.37px for a 2-post tag instead of 11.25px, so the ranking must be reproduced exactly. Tags are ordered by name, byte-wise and case-sensitively, which is why "GSM" precedes "Gist" and "x64" renders last. Hugo's `sort` collates rather than comparing bytes, so the order is pinned from master's rendered cloud as cloud_order and sorted numerically here. See tools/generate_content.py. */ -}} {{- $tagpages := sort (where site.Pages "Type" "tagpage") "Params.cloud_order" -}} {{- $allCounts := slice -}} {{- range $tagpages -}}{{- $allCounts = $allCounts | append .Params.post_count -}}{{- end -}} {{- $distinct := sort (uniq $allCounts) -}} {{- $span := sub (len $distinct) 1 -}} {{- $minF := site.Params.tagcloudMinFont -}} {{- $maxF := site.Params.tagcloudMaxFont -}}
